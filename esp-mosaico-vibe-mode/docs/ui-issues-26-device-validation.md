## 2：左滑卡顿

连续五组主页左滑至 Ideas、右滑回主页，十次翻页均成功。测试窗口记录
80 个注入输入和 336 个重绘帧（包含往返结束后的主页动画）。

| 设备端阶段 | 中位数 | 最大值 |
| --- | ---: | ---: |
| UI tick | 0.146 ms | 1.488 ms |
| 软件绘制 | 31.499 ms | 33.396 ms |
| 屏幕提交 | 42.858 ms | 52.844 ms |
| 单次重绘循环 | 75.007 ms | 85.007 ms |
| 输入队列等待 | 6.039 ms | 86.369 ms |
| 指针处理 | 0.007 ms | 0.561 ms |

`factory_ui.c::render_task()` 在同一任务、同一锁内依次处理输入、读取物理
触摸、整帧绘制、提交屏幕。主页动画变化会触发完整 480×480 重绘；
`present_frame()` 逐块复制并提交整帧。绘制和提交期间不会再次采样触摸或
消费注入队列。左滑松手后的切页逻辑耗时很短，主要延迟在前面的帧工作。

本轮定位到可测量的输入阻塞，未复现秒级死锁。当前横向手势在松手时切页，
没有跟手的横向过渡动画。后续修复应减少主页动画的重绘/传输范围，并让
输入采样不受整帧提交阻塞；需用真实手指快滑验证短手势漏采。本轮不改滑动实现。

证据：工作树 `.codex-runs/issues-26/swipe-window.log`、
`swipe-summary.json`；消费工作区 `.codex-runs/evidence/swipes.jsonl`。

## 6：振动增强

用户已确认普通点击和较长的双振动都能感受到，并将需求收敛为增强振动，
不再调整其他触感行为。BSP 的 `bsp_motor_set(true)` 已使用 100% PWM，
因此通过将每个通电脉冲的时长加倍增强体感；这不是将物理振幅翻倍。

| 模式 | 原脉冲（ms） | 新脉冲（ms） | 中间间隔（ms） |
| --- | --- | --- | --- |
| 1 | 8 | 16 | 无 |
| 2 | 8 / 8 | 16 / 16 | 45 |
| 3 | 24 | 48 | 无 |
| 4 | 14 / 22 | 28 / 44 | 70 |
| 5 | 40 / 40 | 80 / 80 | 60 |

实机对模式 1、3、5 各触发两次，驱动调用均返回 ESP_OK。定时回调测得：
模式 1 为 16.274–16.279 ms，模式 3 为 48.212–48.217 ms；模式 5 首脉冲
约 80.2 ms、第二脉冲约 80.2 ms，中间间隔约 60.2 ms。开关、事件映射、
调度及其他触感逻辑保持原样。证据为
`.codex-runs/issues-26/haptic-doubled-telemetry.log`。
