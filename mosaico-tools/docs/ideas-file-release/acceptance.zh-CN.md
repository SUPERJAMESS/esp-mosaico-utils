## 2026-10-14 NAND 分层计数、页缓存与短事务复验

本轮依次加入物理 SPI/逻辑页计数、64 KiB PSRAM 逻辑页 LRU 缓存、NAND 短事务
polling。缓存位于 LittleFS 与 Dhara 之间，写入、擦除、ioctl、sync 及读错误均使
缓存失效；数据读取仍走中断/DMA。没有改变 NAND 磁盘格式、ECC、40 MHz SIO，
没有加入整镜像缓存、QIO 或提高时钟。

为排除不同工作任务运行状态的干扰，使用独立只读测试组件，对同一份 1,295,904
字节应用镜像，在 CPU 0/1 分别固定读取任务；每核各测试暂停渲染、正常界面及
10 Hz 文字刷新，各重复两轮。缓存组每次先读取另一份大于缓存的文件排出目标页。
下表为 `fread` 累计时间，不含 SHA-256、文件打开/关闭或安装器的调度让步。

| 配置 | 样本数 | 平均读取 | 读取范围 | 物理页读取次数 |

### 为什么正常任务曾经慢很多

ESP32-S31 当前开启 `ESP_SYSTEM_ALLOW_RTC_FAST_MEM_AS_HEAP`，普通 INTERNAL/8BIT
堆包含 HP SRAM 和 LP/RTC RAM。默认动态创建的 16 KiB Ideas 栈会受连续空闲块分布
影响；“内部缓冲”不能说明任务栈也在 HP SRAM。PSA 软件 SHA 状态、局部数组和
存储驱动调用栈因此可能访问较慢的 RTC RAM。

只读对照保持同一文件、4096 字节 HP SRAM 缓冲和 SHA 实现，分别在 CPU 0/1
使用默认 8/16 KiB 栈、强制 16 KiB SRAM 栈、强制 16 KiB RTC 栈。24 条 NAND/NOR
记录均为 1,295,904 字节，SHA-256 均为
`2ffd92edb1878aa7f3966688a285aa45a18b9c63fb0d5ca17e950c4f5f8047c5`，结果码均为 0。
16 KiB SRAM 对比 RTC：NAND 读取均值 0.701/4.618 s，SHA 0.192/3.819 s；
NOR 栈上缓冲回读 0.153/2.620 s，SHA 0.194/4.064 s。两颗核结果一致。

随后用正常 UI 安装同一 900001：普通候选的实际栈位于 `0x2f049xxx` SRAM；
仅改变测试栈内存能力的诊断候选位于 `0x2e003xxx` RTC。两者均为 16 KiB 栈、
优先级 3、不绑核，使用相同发布内容，均已启用本轮验证去重。

| 阶段 | 正常候选 SRAM 栈 | RTC 栈对照 |
| --- | ---: | ---: |
| 完整安装 | 14.839 s | 57.238 s |
| 完整文件预检 | 3.915 s | 13.199 s |
| 应用 NAND 读取 | 0.710 s | 4.622 s |
| 应用源 SHA | 0.191 s | 3.805 s |
| 应用 NOR 写入 | 3.878 s | 9.957 s |
| 应用 NOR 擦除及准备 | 3.599 s | 3.593 s |
| 应用 NOR 回读及 SHA | 0.346 s | 6.689 s |
| 应用完整镜像检查，仅一次 | 0.261 s | 4.232 s |

分段行不是完整安装的穷尽拆分；NOR 回读和镜像检查属于应用组件结束阶段。
擦除基本不变，读取、写入、SHA 和镜像检查的 CPU 开销随栈位置显著变化。
这解释了此前固定任务快、正常任务慢的主要原因，也说明更换 CRC16 并不能消除
所有额外耗时。原 60.802 s 与本轮 RTC 57.238 s 都包含慢栈开销；不能把
60.802 → 14.839 s 全部算作验证去重。去重消除的是原提交阶段约 4.2 s 的第二次

## 2026-10-14：常驻 HP SRAM worker 与显示 DMA 内存预算

Ideas 在 Wi-Fi 驱动启动后一次性申请 16 KiB INTERNAL/8BIT/DMA 栈，保留优先级 3
和不绑核策略。长度为 1 的指针队列串行承接扫描、预览、下载、安装和语言切换；
工作任务完成一项后等待下一项，不再销毁/重建。初始化最后发布可用状态，部分
资源分配失败全部回收，返回 ESP_ERR_NO_MEM 并允许重试，不回退到 RTC/PSRAM。
空闲时保留工作栈及控制结构是本次策略的内存成本。

实机同时暴露了显示 DMA 竞争：旧候选也有 LCD 分配失败，常驻栈后切换语言和

描述符对齐，并在回收事务结果时释放临时 DMA 副本，已完成但未回收的块也占内存。
Vibe 的初始化适配现仅对板载 LCD 请求 3840 字节总线块、深度 1，实际临时数据
约 4 KiB，另有分配器/事务开销；保留频率、接线、PSRAM DMA 策略及 NAND 设置。
BSP 和 IDF 源码未修改。减少排队重叠是代价，实机全屏传输仍可能超过一个 TE 周期；
此变更不承诺 60 fps 全屏刷新。
